# Architecture Decision Records

## 철학

운영 비용 월 $0. 외부 의존성 최소화. 영구 데이터는 파일(git)에 두고, 휘발성 수치만 DB에 둔다. 작동하는 최소 구현을 선택한다.

---

### ADR-001: 글 본문은 git 레포의 MDX 파일로 저장

**결정**: 글은 `content/{category}/YYYY-MM-DD-slug.mdx`. 발행은 관리자 UI가 GitHub Contents API로 커밋 → Vercel 자동 재배포.
**이유**: 비용 0, 무제한. 버전관리·롤백·백업이 git으로 공짜. DB가 죽어도 글은 살아 있다. Vercel 서버리스는 파일시스템이 읽기 전용이라 앱이 자기 콘텐츠를 못 쓰므로 외부 저장이 어차피 필요하다.
**트레이드오프**: 발행 후 사이트 반영까지 빌드 시간(~90초) 지연. 글 수가 수천 건이 되면 빌드가 느려진다 (현재 규모에선 무관).

### ADR-002: Turso는 휘발성 수치 전용

**결정**: Turso(libSQL)에는 조회수만 넣는다. 본문·인증정보·댓글은 넣지 않는다.
**이유**: 정적 생성으로는 조회수 같은 실시간 수치를 못 다룬다. Turso 무료 티어는 5GB·무활동 정지 없음. Supabase는 7일 무활동 시 프로젝트가 정지되어 조용한 개인 블로그에 부적합.
**트레이드오프**: 외부 서비스가 하나 늘어난다. 대신 죽어도 글 읽기에는 영향이 없도록 조회수 실패는 무시한다.

### ADR-003: MDX 컴파일 경로 단일화

**결정**: `next-mdx-remote/rsc` 하나로 파일 기반 콘텐츠와 관리자 실시간 프리뷰를 모두 처리한다. 컴파일 진입점은 단 하나.
**이유**: 프리뷰와 실제 렌더가 다른 파이프라인이면 "프리뷰는 되는데 발행하면 깨진다"가 반드시 생긴다.
**트레이드오프**: 빌드 타임 전용 방식(contentlayer 등)보다 약간 느리다.

### ADR-004: 댓글은 Giscus (GitHub Discussions)

**결정**: 자체 댓글 저장소를 만들지 않고 Giscus를 임베드한다.
**이유**: 비용 0, 서버 코드 0, 스팸 관리를 GitHub에 위임. 독자층이 개발자라 GitHub 계정 장벽이 낮다.
**트레이드오프**: GitHub 계정 없는 독자는 댓글을 못 단다.

### ADR-005: **우리가 만든** 이미지는 레포에 커밋한다 (R2 사용 안 함)

**결정**: 업로드 이미지는 글과 **같은 방식으로 GitHub 레포에 커밋**한다 (`public/uploads/{YYYY}/{MM}/`). Cloudflare R2 를 쓰지 않는다. 샘플/정적 이미지는 `public/` 그대로.
**이유**: 글 발행이 이미 GitHub Contents API 커밋이므로 이미지도 같은 경로를 타면 **외부 서비스가 하나도 늘지 않는다.** 계정·버킷·도메인·API 키 설정이 통째로 사라지고, 이미지가 글과 함께 버전관리·롤백된다. 개인 블로그 규모(글당 이미지 몇 장)에서는 레포 용량이 문제되지 않는다.
**트레이드오프**: git 은 바이너리에 약해 이미지가 수백 MB 규모가 되면 clone 이 느려진다. Vercel 의 이미지 최적화도 비용이다 — 현재 팀은 Pro 라 정액 한도가 아니라 **사용량 과금**이므로, 이미지가 늘면 한도에 막히는 대신 요금이 오른다. 그 지점에 도달하면 R2 로 옮기되, 그때는 이미 발행 파이프라인이 있으므로 업로드 대상만 바꾸면 된다.
**대안 검토**: R2 는 10GB 무료 + egress 무료로 용량·성능은 낫지만, 지금 규모에서 그 이점보다 설정 비용과 의존성 증가가 크다.

**2026-08-20 개정 — 범위를 「우리가 만든 이미지」로 좁힌다.** 이 결정이 말하는 이미지는
**우리가 만들거나 직접 잰 것**(관리자가 올린 도표·스크린샷·측정 그림)뿐이다.
**남의 원문 그림은 레포에 복제하지 않는다 — 원본 주소를 그대로 임베드한다** (`source.image`, ADR-014).
옛 문장은 「이미지도 레포에 커밋한다」라 원문 그림까지 받아 두라는 말로 읽혔는데, 그렇게 하면
저작권 판단을 편당 사람이 해야 하고 레포가 남의 바이너리로 부푼다. 위 트레이드오프의
「이미지가 수백 MB 규모가 되면」도 그래서 훨씬 먼 이야기가 됐다.

### ADR-006: 인증은 Auth.js v5 GitHub OAuth + 계정 화이트리스트

**결정**: 로그인은 GitHub OAuth (`next-auth@beta`, v5). `signIn` 콜백에서 허용 login 화이트리스트로 대조하고, `/admin/*`은 `src/proxy.ts`로 막은 뒤 각 페이지·라우트에서 세션을 다시 확인한다. 발행 커밋은 **별도의 fine-grained PAT**을 쓴다.
**이유**: 비밀번호 관리 불필요. OAuth 토큰에 `repo` 스코프를 주면 계정 전체 레포 권한이 열리므로, 커밋용은 이 레포 하나에만 권한이 있는 PAT으로 분리한다. proxy(구 middleware)는 Next.js 공식 문서상 유일한 방어선이 되어선 안 되므로 페이지 레벨에서 한 번 더 확인한다.
**트레이드오프**: 시크릿이 하나 늘어난다. 대신 권한 폭발 반경이 레포 하나로 제한된다.

### ADR-008: Tailwind v4 CSS-first 토큰

**결정**: `tailwind.config.js` 를 만들지 않는다. 디자인 토큰은 `src/app/globals.css` 에서 CSS 변수 + `@theme inline` 으로 선언하고, 다크모드는 `@custom-variant dark (&:where(.dark, .dark *));` 로 클래스 기반 토글을 쓴다.
**이유**: Tailwind v4 의 기본 방식이며 토큰이 CSS 한 곳에 모인다. v4 의 `dark:` 는 기본이 `prefers-color-scheme` 이라 사용자 토글을 지원하려면 custom-variant 선언이 반드시 필요하다 (실제 빌드로 검증함).
**트레이드오프**: v3 문법(`tailwind.config.js`, `darkMode: 'class'`)에 익숙한 예제를 그대로 못 쓴다.

**2026-08-20 개정** — `@custom-variant` 의 방향이 뒤집혔다. **밤이 기본 지면이 되면서 변형은
`light` 쪽이다**: `@custom-variant light (&:where(.light, .light *));` (ADR-010).
`tailwind.config.js` 를 만들지 않는다는 결정과, 토큰을 CSS 한 곳에 모은다는 이유는 그대로다.
토큰 블록의 구성은 ADR-012 가 다시 정했다 — `@theme static`(원료) + `:root`/`.light`(역할) +
`@theme inline`(역할 → 유틸리티).

### ADR-007: 검색은 DB 없이 클라이언트에서

**결정**: 빌드 타임에 JSON 검색 인덱스를 생성하고 `minisearch`로 클라이언트에서 검색한다.
**이유**: 글 수백 건 규모에서 인덱스는 수백 KB. 서버·DB 없이 즉시 응답.
**트레이드오프**: 글이 수천 건이 되면 인덱스 전송량이 문제가 된다. 그때 재검토한다.

**2026-08-19 개정** — 색인에 `source.title`(원문 제목)과 `paper.arxivId` 를 더했다. 한글 제목만
색인돼서 `"MobileMem: Learning from a Year of Mobile Experiences"` 를 통째로 쳐도 안 나왔는데,
6개월 뒤에 기억나는 것은 그 영어 문장이다. 편당 694B → 774B(+11%).

**본문은 여전히 넣지 않는다.** 실측으로 본문까지 넣으면 편당 3.6KB 라 하루 20편·1년이면 약 25MB 다 —
「서버 없이 즉시 응답」이라는 이 결정의 전제가 그 자리에서 무너진다. `feed.test.ts` 가 편당 크기를
회귀 네트로 잡는다. **그 단언이 깨지면 숫자를 올릴 것이 아니라** 연도별 샤딩
(`/search-index/{year}.json`, 최신부터)을 꺼낼 때다. 문턱은 색인 1MB.

### ADR-009: 글 주소는 분류에서 분리한다

**결정**: 글 주소를 `/{category}/{slug}` 에서 **`/posts/{slug}`** 로 옮긴다. 카테고리 목록은
`/{category}` 에서 `/sources/{category}` 로 내린다. Turso 의 `post_id` 도 `{category}/{slug}` →
`{slug}` 로 바꾼다.

**이유**: 분류를 주소에 넣으면 **분류를 고칠 때마다 링크가 죽는다.** 이 사이트는 그 개편을 이미
한 번 겪었다 — 2026-08-15 에 `hf-blog` 한 칸이 `releases` 와 `news` 로 갈렸다. 게다가 발행분의
62%가 `papers` 라 주소의 대부분이 「이 글이 무엇인가」가 아니라 「어느 피드에서 왔나」를 말하고 있었다.
덤으로 최상위 동적 세그먼트가 사라지면서 `RESERVED_SEGMENTS` 가 막던 결함(정적 라우트와 충돌하면
404 가 아니라 엉뚱한 페이지가 조용히 뜬다)도 함께 사라졌다.

**트레이드오프**: slug 이 **전역으로** 유일해야 한다 — `getAllPosts()` 가 검사하고 겹치면 빌드를
깨뜨린다(한쪽 글이 영영 안 보이는 것보다 낫다). 수집기가 arXiv ID 나 해시 8자를 붙여서 실제로
겹칠 일은 없다. 조회수 옛 행은 고아가 되지만 지우지 않는다 — 아무도 읽지 않는다.
**오픈 전이라 끊길 외부 링크가 없는 지금이 바꿀 수 있는 유일한 시점이었다.**
이 이후로 `/posts/{slug}` 의 slug 은 바꿀 수 없다 — 대신 카테고리도 축도 언제든 고칠 수 있다.

### ADR-010: 다크가 기본 지면이고 `prefers-color-scheme` 을 보지 않는다

**결정**: `:root` 가 곧 밤이다. 낮은 `<html class="light">` 로만 오고, 그 클래스는 **사람이 토글로 고른 값**(`localStorage`)이 있을 때만 붙는다. `prefers-color-scheme` 을 어디서도 읽지 않는다. Tailwind 변형도 `dark` 가 아니라 `light` 로 선언한다. 지면 판정은 `src/lib/theme.ts` 의 `currentTheme()` 하나로 모은다.

**이유**: 액센트 채도·입체(`--edge-top`)·썸네일 표지가 **전부 밤에 맞춰 정해진다.** OS 설정이 그것을 뒤집으면 **노력의 일부만 들어간 지면이 첫 화면**이 된다 — 반쯤 디자인된 라이트 모드를 만드는 정확한 방법이다. 라이트를 없애는 것이 아니라 **명시적 선택으로 내리는** 것이다.

덤이 셋 있고, 그중 첫째가 크다.

- **기본 경로에 클래스 조작이 아예 없다.** 저장값이 없으면 인라인 스크립트가 아무 일도 하지 않고 `:root` 가 이미 밤이다 → **흰 화면 번쩍임이 구조적으로 사라지고** JS 가 꺼져 있어도 밤이 그려진다.
- 정본 `:root`(밤)와 앱 `:root`(밤)가 **같은 셀렉터**가 되어 동기화 테스트가 직접 비교로 끝난다 (ADR-012).
- 정본의 밤 블록 3중복(`@media` · `[data-theme]` · `.ground-dark`)이 2블록으로 준다.

**값이 쌌던 이유**: 앱에서 `dark:` 유틸리티가 **6곳뿐**이었다. 그 여섯을 `light:` 로 우회하는 것보다 구조를 역전시키는 쪽이 쌌고, 마침 `--cat-*` 다섯 칸이 두 지면 모두에서 4.5:1 을 넘게 되면서 여섯 곳이 통째로 사라졌다.

**트레이드오프**: 낮을 쓰는 사람에게 첫 방문이 밤이다. **라이트 지면을 눈으로 판정한 적이 없다** — 값은 대비 계산으로만 세웠고 회귀 테스트가 4.5:1 을 지키지만 "보기 좋은가"는 미검증이다. 그리고 지면 판정이 흩어지면 뒤집는 개편에서 한 곳씩 빠뜨린다 — 토글·다이어그램·댓글이 각자 클래스를 검사하고 있었고, 코드블록의 shiki 이중 테마도 기본을 `--shiki-dark` 로 뒤집지 않으면 **밤 한가운데 흰 상자**로 남는다.

### ADR-011: 신문 구조를 버리고 균일 피드로

**결정**: 홈을 **일자로 구획된 균일 피드**로 바꾼다. 머리기사·단신·색인 셋으로 급을 나누던 배치를 없애고 **모든 행을 같은 크기**로 그린다. 목록 컴포넌트 넷(`PostTable` · `PostIndexRow` · `PostLead` · `PostBrief`)을 `PostRow` 하나로 합치고, frontmatter 의 `lead` 를 없앤다. 행이 다른 것은 크기가 아니라 **어떤 부호를 달고 있는가**뿐이다 — 추린 비율(행마다, 있는 만큼) · 교차 N곳 · ▲N · 약한 축 †.

**정보구조(IA)는 그대로 둔다**: 일자 구획(`DayHead`) · 릴리즈 접기(`ReleaseDigest`, 예산에서 1행으로 세는 회계 포함) · 축 번호 레일 · 카테고리 강등 · `SinceLastVisit`. **죽은 것은 급의 차이뿐이다.**

**이유**: 신문 배치는 **사람이 하루 한두 편 고르던 시절의 것**이고, 지금은 봇이 하루 스무 편을 밀어 넣는다. 하루치 안에서 「가장 최근 글을 크게」는 **동어반복**이라 실제로는 아무것도 고르지 않았다 — 선정기 3단 중 1단(`lead`)은 60편 전부 `false` 였고 2단(교차등장)은 27%만 걸렀다. 크기가 같아야 스무 행이 훑히고, 그때 눈에 띄는 것은 「크게 그린 것」이 아니라 **「부호가 붙은 것」**이 된다. 행마다 요약을 켜고 끄던 것(`showSummary`)이 곧 비균일이었다.

**트레이드오프**: 「오늘 무엇이 가장 중요한가」를 지면이 크기로 말하지 않는다. 부호가 그 일을 대신하는데 **부호를 못 읽는 첫 방문자에게는 스무 행이 평평하다.** 요약을 한 줄로 자르는 것이 균일의 잠금장치라(두 줄이 되면 그 행만 커진다) 긴 요약이 필요한 글은 손해를 본다. 이 결정을 되돌리려면 그때의 숫자(급이 실제로 무엇을 걸렀는가)를 다시 재야 한다.

**대안 검토**: 선별 등급(`selection.grade`)으로 머리기사를 고르는 안을 넣어 봤다가 되돌렸다 — 발행분의 59%가 `high` 라 후보를 거의 못 좁힌다. 교차등장만 실제로 가르지만(27%) 그것은 급이 아니라 **부호**로 싣는 편이 싸다.

### ADR-012: 토큰을 원료/역할로 가르고 `@theme static` + 동기화 회귀 테스트

**결정**: 토큰 이름 공간을 둘로 가른다.

- `--color-*` · `--text-*` · `--radius-*` = **Tailwind 이름 공간(원료)**. `@theme static` 이 소유하며 지면이 바뀌어도 안 변한다.
- 접두사 없는 이름(`--bg` · `--muted` · `--cat-*` · `--space-*`) = **우리 역할 층**. `:root` / `.light` 가 소유하며 지면마다 갈린다.
- 역할을 유틸리티로 올리는 것은 `@theme inline` 이고, **지면마다 값이 갈리는 것만** 여기 온다.

정본(`design/styles.css`)과 앱(`src/app/globals.css`)의 동기화는 `src/lib/design-tokens.test.ts` 12건이 **두 파일을 파싱해 직접 비교**한다.

**이유**: `--color-chart-2..5` 가 **조용히 죽었던 사건**을 봉인한다. Tailwind v4 는 쓰이지 않는 `@theme` 변수를 빌드에서 제거하고, 없는 변수를 받은 Recharts 는 경고도 빌드 실패도 없이 그냥 검정으로 칠한다. `static` 은 그 제거를 끄고, 테스트 ③은 반대로 「`inline` 에 있으면서 안 쓰이는 이름」을 잡는다. 이름 공간을 가르지 않으면 `@theme inline { --color-bg: var(--bg) }` 가 자기참조라 성립하지 않는다 — 개편 전에 안료 ramp 를 유틸리티로 못 올리고 있던 이유가 그것이다. 동기화는 그동안 일회성 인라인 스크립트로만 확인해서 정본에만 있는 값이 조용히 쌓였다 (`.cat-news` 가 정본에서 여전히 朱土였다).

테스트가 잡는 결함: 정본↔앱 토큰 drift(첫 실행에서 `1.70` 대 `1.7` 을 잡았다) · 죽은 `var(--…)` 참조(안료 ramp 이름을 바꾸며 실제로 6곳이 남았다) · 컴포넌트의 hex/oklch/글꼴 리터럴 · `CAT_CLASS` 다섯 클래스 누락(**CSS 누락은 컴파일러가 못 잡는다**) · sRGB 색역 · 두 지면 AA 4.5:1 · 부호와 액센트의 채도 서열 · 소셜 카드 hex.

**트레이드오프**: 토큰 하나를 옮길 때 세 곳(`@theme static` · `:root`/`.light` · `@theme inline`)을 함께 봐야 한다. 테스트가 CSS 를 정규식으로 파싱하므로 **중첩 규칙을 쓰면 깨진다.** `inline` 에 이름을 먼저 추가하면 유틸리티로 실제 쓰기 전까지 테스트가 빨개진다 — 불편이 아니라 목적이다.

### ADR-013: 간격을 4px 척도로 (「8의 배수가 아니다」 철회)

**결정**: 간격 척도를 `4·8·12·16·24·32·48·64·96` 으로 바꾼다. 옛 척도(`5·9·14·18·28·37·55·74·110`)와 그것을 떠받치던 불변 「손으로 정한 척도 — 간격이 8의 배수가 아니다」를 **철회한다.**

**이유**: `--space-1`~`4` 가 Tailwind 기본 간격과 값이 같아져 `gap-3` 과 `--space-3` 이 어긋나지 않는다. 옛 척도에서는 기본 유틸리티와 임의 값 유틸리티(`mt-[var(--space-3)]`)가 한 화면에 섞이면 5px 과 4px 이 나란히 서 있었다. **5부터는 눈으로 정한 뜀이라 인덱스가 어긋난 채로 남겼다** — `--space-5` 는 20 이 아니라 24다.

**「AI스러움」 진단과의 충돌을 정면으로 적는다.** `docs/UI_GUIDE.md` 와 `design/brief.md` 는 「모든 여백이 8의 배수인 것은 눈으로 보지 않았다는 뜻」이라고 적고 있고, 옛 척도는 그 진단의 산물이었다. **그 진단은 배수를 금지하는 규칙이 아니라 결정 회피를 잡는 질문이다.** 이번 개편의 실제 결정은 stitch 로 화면을 보고 정한 값들 — 액센트 `oklch(0.715 0.190 148)` · radius 4px · 행 높이 96px · 썸네일 80×45 — 에 있고, 간격은 그 값들이 앉을 격자다. 홀수 척도는 결정의 증거가 아니라 결정의 **알리바이**였다. 검사는 대조표가 아니라 질문 하나로 한다: **「이 화면에서 내가 내린 결정이 무엇인가」.** 답이 「기본값을 썼다」뿐이면 척도가 몇 배수든 실패다.

**트레이드오프**: 「간격만 보고도 손으로 정한 티가 난다」는 신호를 잃는다. 그 자리를 부호·고정폭 열·활자 급이 대신하는데, 그것들이 약해지면 지면이 통째로 기본값처럼 보일 위험이 옛날보다 크다. 그리고 이 철회 이후 **「4의 배수라서 괜찮다」는 방어는 성립하지 않는다** — 그건 새 알리바이일 뿐이다.

### ADR-014: 글 썸네일은 원본 주소를 직링크한다 (복제가 아니라 임베드)

**결정**: frontmatter `source.image` 에 **원문 페이지의 그림 주소**를 담고, 목록 행은 그 주소를 `<img src>` 로 그대로 임베드한다. **레포에 받아 두지 않는다** (ADR-005 의 커밋 규칙은 우리가 만든 이미지에만 적용된다). `next/image` 를 쓰지 않고 `next.config.ts` 의 `remotePatterns` 도 열지 않는다. 주소가 없거나 죽은 글에는 **카테고리 안료를 지면에 16% 섞은 표지**가 같은 크기로 선다.

**이유**

- **`source` 안에 두는 것이 핵심이다.** 「이 그림은 `source.url` 페이지에서 왔다」가 관례가 아니라 **구조**가 되어 출처가 어긋날 방법이 없어진다. `notes`(사람이 쓴 글)에는 `source` 가 없으니 저절로 표지로 떨어진다 — 게이트를 따로 만들 필요가 없다.
- **`next/image` 를 안 쓰는 이유.** 최적화기를 태우면 Vercel 이 원본을 받아 변환해 **우리 인프라에 파생 사본을 캐시하고 우리 도메인에서 재배포**한다. 「복제가 아니라 임베드」라는 근거가 그 자리에서 사라진다.
- **`remotePatterns` 를 안 여는 이유.** `"**"` 는 `/_next/image?url=` 을 **공개 이미지 프록시**로 만든다. 호스트를 열거하는 방식은 목록에 없는 호스트가 발행되는 순간 **프로덕션 500** 이다. 안 열면 이 질문 자체가 사라진다. `PostThumb.test.tsx` 가 렌더 결과에 `/_next/image` 가 없음을 고정한다.
- **`referrerPolicy` 를 덮어쓰지 않는다.** 호스트가 누가 임베드하는지 보고 원치 않으면 막을 수 있어야 하고, **그 통제권이 상대에게 남는 것이 임베드의 실질이다.**
- 실패는 자바스크립트 없이 두 층으로 받는다 — 주소가 없으면 `<img>` 를 안 그려 표지가 보이고, 주소가 죽으면 브라우저가 그 자리를 안 그려 표지가 뒤에서 비친다.

**트레이드오프**: srcset·AVIF 가 없다 — 80×45 에서 무의미하고 수집기가 애초에 작은 원본을 고른다(유튜브 `hqdefault` 480×360 ≈ 20KB). 원본이 사라지면 그림이 빈다(표지로 떨어진다). 호스트가 hotlink 를 막으면 우리가 할 수 있는 일이 없다 — 그것이 이 결정의 값이다. 레이아웃 시프트는 상자 크기를 고정해서 막는다.

**대안 검토**: 호스트 화이트리스트를 zod 스키마에 두는 안 — 스키마 실패는 `next build` 를 깨뜨리므로 **처음 보는 호스트 하나가 사이트 전체를 못 세운다.** 어느 그림을 버릴지는 수집기가 정한다. 스키마가 막는 것은 `https` 가 아닌 주소뿐이다(http 그림은 브라우저가 막아 빈칸이 된다). 검색 색인에는 썸네일 주소를 넣지 않았다 — 결과 목록이 색인 밀도라 자리가 없고, URL 을 얹으면 편당 900B 예산(`feed.test.ts`)이 즉시 깨진다.
