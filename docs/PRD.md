# PRD: 초록

## 목표

HuggingFace 블로그·arXiv 논문 등 영문 AI 최신 동향을 한글 요약으로 정리해 공개하는 1인 운영 사이트.

사이트 이름은 **초록**(논문의 abstract). 원문을 그대로 옮기는 번역이 아니라 **추려 적는 것**이 이 사이트가 하는 일이다 — 이름·문구·출처 표기가 전부 그 사실에 맞아야 한다.

## 사용자

- **독자** (외부 공개): AI 기술 동향을 한글로 빠르게 훑고 싶은 개발자·연구자. 로그인 없이 열람, GitHub 계정으로 댓글.
- **운영자** (1명): 글을 작성·발행·수정한다. GitHub OAuth 로그인.

## 카테고리

설정 파일로 데이터화한다. 카테고리 추가는 설정 수정만으로 되어야 한다.

**slug 은 고정이다.** 이미 발행된 글 주소·RSS·sitemap 이 걸려 있으므로 바꾸지 마라. 화면 표기만 바꿀 수 있다.

| slug | 이름 | 짧은 이름 (목록용) | 성격 |
|---|---|---|---|
| `hf-blog` | 허깅페이스 소식 | 소식 | HF 블로그 글 요약 + 원문 링크 |
| `papers` | 최신 논문 | 논문 | arXiv 논문 리뷰. 수식·도표 비중 높음 |
| `notes` | 수집 자료 | 메모 | 개인 스크랩·메모 |

밀집 목록의 구분 열에는 짧은 이름을, 카테고리 페이지 제목에는 긴 이름을 쓴다.

## 핵심 기능

**공개**
1. 홈 — 마스트헤드 + 최신 글 목록. **첫 화면에서 글이 보여야 한다** (히어로가 화면을 차지하지 않는다)
2. 카테고리별 목록 (페이지네이션·태그 필터)
3. 글 상세 — TOC, 출처·라이선스 표기, 읽기 시간, 이전/다음
4. 본문 표현 — 수식(KaTeX) · 차트(Recharts) · 다이어그램(Mermaid) · 고급 표 · 이미지(캡션·확대)
5. 검색(클라이언트), RSS, sitemap, OG 이미지
6. 댓글(Giscus), 조회수
7. **태그 색인** — 태그별 글 수와 태그별 목록
8. **아카이브** — 연·월별 발행 목록
9. **소개** — 운영 원칙, 번역이 아니라 요약이라는 점, 출처·인용 정책, 오류 제보 경로

**관리자** (`/admin`, 로그인 필수)
10. 글 목록 대시보드 (발행/초안, 조회수)
11. MDX 에디터 + 실시간 프리뷰
12. GitHub 커밋으로 발행 → Vercel 자동 재배포
13. 이미지 업로드 — 글과 같은 방식(GitHub 커밋)으로 같은 레포의 `public/uploads/` 에 저장 (ADR-005). 외부 스토리지를 쓰지 않는다. 글 저장과 원자적으로 한 커밋일 필요는 없다.

## MVP 제외 사항

- HuggingFace/arXiv **자동 수집** — 별도 phase
- Claude API 자동 요약·번역 생성 — 별도 phase
- 다중 저자 / 권한 등급
- 뉴스레터·이메일 발송
- 다국어 (한글 전용)

> **광고·유료화는 제외 목록에서 뺐다.** Vercel Pro 라 약관상 제약이 없다. 다만 지금 범위도 아니다 —
> 도입하려면 별도 결정과 phase 가 필요하다. **요청 없이 광고 스크립트나 결제를 넣지 마라.**

## 디자인

- 읽기 우선. 콘텐츠가 주인공이고 UI는 물러난다.
- **개인 블로그가 아니라 연구 피드처럼 보여야 한다.** 목록은 조밀한 표, 본문은 넉넉한 단폭.
- 라이트/다크 양쪽 지원 (장문 독해용).
- 중성 무채 베이스 + **카테고리 3색**(정보 부호로만 사용). **보라/인디고 금지.**
- 본문은 세리프, UI는 산세리프, 데이터·코드는 모노. **한글에도 웹폰트를 지정한다** — 안 그러면 OS마다 다르게 보이고 한 문장 안에서 서체가 갈린다.
- **균일한 반복을 피한다.** 모든 구역이 같은 구조·같은 여백이면 만들다 만 템플릿처럼 보인다.
- 상세는 `docs/UI_GUIDE.md`.
