이 프로젝트의 변경 사항을 리뷰하라.

먼저 다음 문서들을 읽어라:

- `/CLAUDE.md`
- `/docs/PRD.md`
- `/docs/ADR.md`
- `/docs/ARCHITECTURE.md`
- `/docs/UI_GUIDE.md` (UI 변경이 있는 경우)

그런 다음 변경된 파일들을 확인하고, 아래 체크리스트로 검증하라.

## 체크리스트

1. **아키텍처 준수**: `ARCHITECTURE.md` 에 정의된 디렉터리 구조를 따르는가? 계약되지 않은 임의 디렉터리 신설 없음?
2. **기술 스택 준수 (ADR)**: `ADR.md` 에 기록된 결정 사항을 위반하지 않았는가? 의도된 트레이드오프를 우회하기 위한 비공식 의존성 추가 없음? 신규 ADR 이 필요한 변경이라면 ADR 추가 여부 확인.
3. **CRITICAL 규칙 (CLAUDE.md)**: `CLAUDE.md` 의 `CRITICAL:` 마커 규칙을 위반하지 않았는가?
4. **프로젝트 불변식**: `ADR.md` · `CLAUDE.md` 에 명시된 도메인 불변식 (예: 멀티테넌트 격리, 데이터 주권, lineage 추적, 감사 로깅 등 — 프로젝트마다 다름) 을 코드 경로 전반에서 강제하는가? 우회 분기 없음?
5. **외부 의존성 / 비용 경계**: 외부 API · LLM · 결제 · 저장소 호출이 합의된 게이트웨이 / 팩토리 / 어댑터를 경유하는가? 단일 provider 하드코딩 없음?
6. **테스트 존재**: 신규 기능에 단위/통합 테스트가 동반되는가? (`pytest`, `vitest`, `pnpm --filter <app> test/build`, `playwright` 등 스택에 맞는 것) 기존 테스트를 깨뜨리지 않았는가?
7. **AC 실행 검증**: step 에 명시한 Acceptance Criteria 커맨드가 실제로 에러 없이 통과하는가? (복붙 실행으로 확인)
8. **하네스 자가 회귀**: `scripts/execute.py` 또는 `phases/` 스키마를 건드린 경우 `pytest scripts/test_execute.py -q` 통과?
9. **PRD 일치**: 변경이 `PRD.md` 의 목표 · 핵심 기능 범위 안에 있는가? MVP 제외 사항을 슬그머니 구현하지 않았는가?
10. **UI 변경이 있는 경우**: `UI_GUIDE.md` 의 디자인 원칙 · 색상 토큰 · 컴포넌트 규약 · 애니메이션 허용 목록 · AI 슬롭 안티패턴을 준수하는가?
