오라클의 AI 데브렐 이냐시오 마르티네스는 언어 모델(LLM)을 단순한 추론 엔진으로 규정한다. 실제 에이전트의 성능과 안정성은 모델을 감싸는 하네스(Harness)와 메모리 구조에 달려있다는 것이다. 따라서 개발자는 추론 능력은 외부 모델에 의존하되, 메모리와 하네스 제어권은 반드시 스스로 쥐어야 한다.

다중 에이전트 환경에서는 작업 충돌을 막기 위해 파일 시스템과 데이터베이스를 적절히 구분하는 워크트리 전략이 필요하다. 또한 RAG 파이프라인으로 인한 데이터 파편화나 컨텍스트 부패(Context Rot) 문제를 해결하기 위해서는 에이전트의 지각 렌즈인 '움벨트(Umwelt)'와 툴박스 패턴을 적용해야 한다. 이는 어텐션 비용을 절감하고 문맥의 질을 유지하는 데 필수적이다.

반복되는 워크플로우를 영구 자산으로 승격시키는 '스킬 승격(Skill Promotion)' 기법도 중요하다. 이를 통해 에이전트는 일회성 작업을 재사용 가능한 능력으로 발전시킬 수 있다. 이 글은 이러한 개념들을 바탕으로 19가지 단계별 실습을 통해 프로덕션급 에이전트 하네스를 구축하는 방법을 제시한다.

원문의 전문은 다루지 않았으므로, 구체적인 코드 예시나 상세한 아키텍처 다이어그램은 생략했다. 더 깊이 있는 내용을 원하면 제공된 링크를 통해 오라클의 AI 데브렐 이냐시오 마르티네스의 전체 세션 자료를 참고할 것을 권장한다.
