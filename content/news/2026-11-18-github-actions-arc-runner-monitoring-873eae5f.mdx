GitHub Actions를 운영하다 보면 특정 Job이 실행되지 않고 Queued 상태에 머무는 상황이 발생한다. 당근에서는 Kubernetes 환경에서 ARC를 통해 self-hosted Runner를 관리하고 있지만, 기본적으로 제공되는 메트릭만으로는 특정 Job이 어떤 Runner Pod에서 실행되는지, 혹은 왜 대기 중인지에 대한 세부 정보를 파악하기 어려웠다.

기존의 ARC 메트릭은 Runner와 Job의 집계 현황은 보여주지만, 실시간 대기 시간이나 개별 Job의 배정 상태를 추적하기에는 한계가 있었다. 이를 해결하기 위해 컨트롤러의 구조적 변경 없이도 데이터를 수집할 수 있는 별도의 모니터링 체계가 필요했다.

결국 당근 SRE팀은 Runner Pod와 Job의 관계를 매핑하고 대기 중인 Job까지 추적할 수 있는 action-runner-job-exporter를 자체 제작했다. 이 시스템은 Runner Pod에 Job 이름을 부여하는 Collector, 대기 중인 Job을 추적하는 Webhook, 그리고 상태를 저장하는 StateStore로 구성되어 운영 효율을 높였다.
