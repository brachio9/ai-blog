vLLM 사용자 정의 플러그인 제작 이후 남은 과제는 반복적이고 복잡한 모델 변환 작업이었다. Hugging Face 모델을 vLLM에 올리는 과정은 단순한 코드 마이그레이션이 아니라, 가중치는 유지하되 실행 방식을 완전히 재작성해야 하는 까다로운 작업이다. 모델 내부 구조를 아는 개발자와 vLLM 인프라를 아는 엔지니어 사이에 존재하는 지식 공백과, 빠르게 변화하는 프레임워크 버전 추적이 주요 장애물이었다.

이 문제를 해결하기 위해 팀은 AI-native 접근법을 선택했다. Anthropic의 코딩 에이전트 CLI인 Claude Code의 Skill 기능을 활용해 변환 절차를 정의하고 자동화했다. 사용자는 Hugging Face 모델 경로만 입력하면, 환경 구성부터 모델 유형 판단, 코드 생성, 테스트 작성까지 다섯 단계의 하위 스킬이 순차적으로 실행된다. 이 과정에서 입출력 전후처리가 필요한지 여부는 모델 유형에 따라 자동으로 결정되며, 최종적으로 PR 생성까지 이어진다.

특히 중요한 단계는 동등성 검증이다. Hugging Face 원본 모델과 vLLM 변환 모델의 출력이 동일한지 확인하는 테스트와 성능 측정을 자동화했다. 이를 통해 서로 다른 유형의 7개 모델을 동일한 절차로 변환해 운영에 적용할 수 있었다. 또한 변환 과정에서 발견한 주의 사항들을 재사용 가능한 지식으로 축적하고, 필요한 시점에만 해당 지식을 불러오도록 구조를 개선해 토큰 사용량을 대폭 줄였다.

이 자동화 파이프라인은 단순한 코드 생성을 넘어 GitHub Issue 작성 하나로 변환부터 배포까지 이어지는 E2E 프로세스로 확장되었다. 두 도메인의 지식 교차와 프레임워크의 빠른 변화를 사람이 직접 따라가기 어려운 상황에서, 검증된 순서와 판단 기준을 재사용하는 AI 에이전트 도입이 실질적인 해결책이 되었다. 전체 구조와 구체적인 구현 상세는 원문을 참고하면 된다.
