이번 업데이트는 에이전트 플러그인 관리를 허브(Hub)가 직접 담당하도록 개선했다. 이제 호스트의 특정 디렉토리에 있는 플러그인은 자동으로 발견되고 유효성 검사되며, 기존에 수동으로 설정 파일을 수정해야 했던 MCP 서버 실행 과정이 간소화되었다. 작업 공간 내의 플러그인 스캔은 명시적 허용이 없으면 작동하지 않아 보안상 우연한 서버 실행을 방지한다. 또한 플러그인 활성화 상태 변경 시 클라이언트가 별도로 저장소를 관리할 필요가 없어졌으며, 기존에 존재하던 스킬 비활성화 버그와 메모리 내 MCP 매니저의 프로세스 누수 문제도 함께 해결되었다.

AI 모델 호출 중 발생할 수 있는 일시적 오류에 대한 대응이 강화되었다. 스트리밍 도중 제공자 측에서 429 에러 등 일시적 문제가 발생하면 전체 실행이 중단되지 않고 최대 3회까지 지수 백오프(exponential backoff) 방식으로 재시도한다. 이미 텍스트나 도구 호출 결과가 일부 스트리밍된 턴은 중복 방지를 위해 재시도하지 않는다. 또한 요청 시작 단계에서 발생하는 네트워크 오류나 서버 에러에 대한 SDK 레벨의 재시도 횟수도 기존 2회에서 5회로 증가하여 안정성이 높아졌다.

스트리밍 성능이 크게 개선되었다. 이전에는 에이전트 루프가 각 토큰 스트리밍마다 클라이언트 훅을 통해 전체 세션 스냅샷을 주고받는 방식이었다면, 이제는 텍스트나 도구 업데이트 델타만 전송하지 않아 직렬화 오버헤드와 IPC 대기 시간이 줄었다. 허브 이벤트 로그의 파일 동기화 방식도 변경되어 각 델타 추가 시마다 발생하는 fsync 호출이 제거됨으로써 스트리밍 속도가 더 이상 훅 포워딩에 의해 제한받지 않는다.

체크포인트 생성 시의 성능 병목 현상이 해결되었다. 이전에는 매 턴마다 작업 공간 내 추적되지 않은 파일 전체를 다시 해싱하여 수 GB의 데이터가 있을 경우 메시지 전송이 몇 분간 지연되는 문제가 있었다. 이제 세션당 지속 가능한 스냅샷 인덱스를 사용하여 변경되지 않은 파일을 건너뛰므로, 두 번째 턴부터는 체크포인트 생성 비용이 크게 절감된다. 또한 손상된 인덱스나 잠금 파일로 인한 세션 고장도 자동으로 복구되도록 개선되었다. 마지막으로 백그라운드 프로세스 실행 시 명령어 실행기가 무한 대기하는 버그도 수정되었다.
