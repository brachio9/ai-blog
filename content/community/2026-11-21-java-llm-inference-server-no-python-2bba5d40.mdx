저자는 파이썬을 전혀 사용하지 않는 실행 환경을 만들기 위해 Java 25의 Project Panama(Foreign Function & Memory API)를 활용했다. 이를 통해 vLLM이나 SGLang 같은 외부 프로세스를 호출하는 대신, C++/CUDA로 작성된 라이브러리와 온닉스런타임(ONNX Runtime)을 Java에서 직접 호출하는 구조를 설계했다.

특히 Qwen 3.8-27B-FP8 모델을 단일 40GB GPU에서 구동하기 위해 메모리 관리와 커널 최적화에 집중했다. 모델 로드 시 발생하는 메모리 점유 문제를 해결하기 위해 플레이스홀더 GEMM 초기화 방식을 도입했으며, GatedDeltaNet 구조에서 공유 메모리 대신 레지스터 기반 커널을 사용하여 연산 비용을 대폭 절감했다.

이러한 최적화를 통해 저자는 Qwen 모델의 추론 속도를 개선했으며, 멀티 GPU 서버뿐만 아니라 리소스가 제한된 기기에서도 작동하는 엔진을 구축했다. 이는 파이썬 의존성을 제거하면서도 고성능 추론을 유지하려는 시도로 평가된다.
