코딩 에이전트에게 대규모 작업을 맡기면 자주 마주치는 문제가 있다. 에이전트가 '구현 완료'라고 선언하지만 실제로는 테스트가 통과하지 않거나 작업이 반쯤 멈춰 있는 경우가 빈번하다. 이는 에이전트의 능력 부족보다는 종료 조건에 대한 판단 기준 부재에서 비롯된다. 대화 컨텍스트가 길어질수록 에이전트는 남은 작업을 완료로 착각하고 작업을 중단한다.

저자 lidangzzz는 이러한 문제를 해결하기 위해 Goal-Driven이라는 방식을 제안했다. 이 방식은 작업 완료 판정을 수행하는 서브 에이전트에게서 분리해 별도의 마스터 에이전트가 담당하도록 한다. 사용자는 목표와 완료 기준을 미리 정의해 두고, 마스터 에이전트는 이 기준에 따라 서브 에이전트의 결과를 검증한다. 기준에 미치지 못하면 동일한 이름의 서브 에이전트를 다시 생성해 작업을 계속하게 함으로써, 저자에 따르면 단일 문제에 대해 300시간 이상 연속 작업이 가능하다고 주장한다.

Goal-Driven 저장소에는 실행 가능한 코드나 패키지가 포함되어 있지 않다. 대신 영문과 중문 README 파일 두 개가 있을 뿐이며, 이 프로젝트의 핵심은 Claude Code나 Codex 같은 도구에 붙여넣어 사용할 수 있는 프롬프트 문안이다. 많은 사용자가 다중 에이전트 시스템을 위한 프레임워크를 기대하고 접근하지만, 실제로는 목표와 완료 기준을 채워 넣는 방법론과 프롬프트 템플릿을 제공하는 것이다.

이 방식은 네 가지 구성 요소로 나뉜다. 목표는 시스템의 최종 지향점이고, 완료 기준은 마스터 에이전트가 작업 종료를 판단하는 명확한 조건 묶음이다. 서브 에이전트는 실제 작업을 수행하며 필요시 하위 작업을 분배하고, 마스터 에이전트는 유일한 통제 주체로서 기준에 따른 최종 결정권을 가진다. 사용자가 직접 설정해야 하는 것은 목표와 완료 기준 두 가지이며, 나머지는 프롬프트를 통해 에이전트들이 처리한다.
