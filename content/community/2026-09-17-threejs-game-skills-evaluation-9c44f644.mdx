코딩 에이전트에게 게임을 만들어 달라고 하면 대개 무언가는 생성되지만, 완성도 측면에서 기대에 미치지 못하는 경우가 많다. 화면에는 회색 정육면체가 떠 있고 인터페이스는 단순한 숫자 카드일 뿐인데, 에이전트는 이를 '완성'된 것으로 보고하는 모순이 발생한다. 이는 에이전트가 자신의 결과물을 판정할 명확한 기준을 갖추지 못했기 때문이며, 개발자는 이러한 간극을 메우기 위해 반복적인 수정 지시를 내려야 하는 비효율적인 과정을 겪게 된다.

마지드 만자푸르는 이 문제를 해결하기 위해 Three.js 게임 제작에 필요한 역할을 9개의 스킬로 나누어 제안했다. 이 프로젝트는 특정 모델이나 유료 API를 요구하지 않으며, Codex와 Claude Code 같은 기존 러너 환경에서 바로 사용할 수 있도록 설계되었다. 핵심은 에이전트가 단순히 코드를 생성하는 것을 넘어, 미리 정의된 시각 품질 점수표(0~3점)와 자동 실패 조건에 따라 자신의 결과물을 스스로 채점하도록 만드는 것이다.

이 방식은 별도의 전용 프레임워크를 구축하거나 단일 게임 검증 하네스를 사용하는 기존 접근법과 차별된다. 저자는 새로운 실행 환경을 만드는 대신, 이미 사용하고 있는 러너의 스킬 디렉토리에 파일을 복사하는 가벼운 방식을 택했다. 이를 통해 설치와 제거가 디렉토리 단위로 처리되며, 에이전트는 브라우저 스크린샷이나 캔버스 픽셀 지표 같은 객관적 증거를 바탕으로 '잘 만들었다'는 주장을 뒷받침해야 한다.

이러한 검증 체계는 코딩 에이전트를 활용하여 브라우저 게임을 개발하려는 사람들에게 유용하다. 별도 도구를 추가로 익힐 필요 없이 기존 워크플로우에 점수표와 실패 조건을 통합함으로써, 에이전트의 자기 평가 능력을 높이고 결과물의 품질을 더 정확하게 파악할 수 있다. 저자는 이를 통해 에이전트가 생성한 게임의 완성도를 수치화하고, 개발자의 피드백 루프를 단축하는 효과를 기대한다.
