개인 정보나 고객 데이터를 사용해 SFT(Supervised Fine-Tuning)를 수행할 때 법무팀이나 보안 담당자는 모델이 학습 데이터를 외우지 않았음을 증명하라고 요구한다. 대부분의 팀은 이에 대한 테스트 결과나 보고서가 없어 답답해하지만, memaudit는 기존 TRL(Transformer Reinforcement Learning) 작업에 두 줄의 코드를 추가해 이를 해결한다. inject() 함수로 교란용 비밀 정보를 데이터셋에 심고 MemorizationAuditCallback을 적용하면 학습 종료 시 버전 관리된 JSON 보고서를 얻을 수 있으며, 이 과정은 외부 서버와 통신하지 않고 Apache-2.0 라이선스로 제공된다.

이 도구는 SFTTrainer의 실제 동작 방식을 고려해 설계되었다. 일반적인 기억력 테스트는 토큰화, 마스크 처리, 길이 제한, LoRA 적용 범위 등의 이유로 테스트 대상이 학습 손실(loss) 계산에 포함되지 않아 위조된 '안전' 결과를 출력하는 경우가 많다. memaudit는 학습 시작 시 모든 교란 데이터가 실제 설정(마스크, 패킹, 최대 길이, 채팅 템플릿 등) 하에서 손실을 받는지 검증하며, 그렇지 않을 경우 가짜 안전 신호를 내보내는 대신 실행을 중단한다.

생성된 보고서는 규제 기관이 구분하는 두 가지 질문에 답한다. 첫 번째는 모델에 접근할 수 있는 공격자가 특정 기록이 학습되었는지 식별할 수 있는지(멤버십)이며, 1%의 오경보 수준에서 신뢰구간과 함께 평가된다. 두 번째는 모델이 학습 기록의 접두사를 보고 해당 내용을 완성하는지(반추)를 정해진 프로토콜 하에 확인한다. 샘플 수가 부족하거나 테스트가 실행되지 않은 항목은 '0'이 아닌 '실행 안 함'으로 명시해 오해를 방지한다.

저자는 TinyLlama-1.1B-Chat과 Alpaca 데이터셋을 사용한 공개 테스트 결과를 제시하며, 중복된 데이터가 유출의 주요 원인임을 주장한다. 이 테스트에서는 멤버십 공격에서 10/100의 탐지율을 보였으나 반추 테스트에서는 0/100의 정확도를 기록했다. 저자는 PEFT 및 TRL 개발자들에게 학습 전 검증 로직의 취약점을 검토해 줄 것을 요청하며, 이번 주에 한 번의 학습 작업에 적용해보라고 권한다.
