코딩 에이전트를 리버스 엔지니어링에 활용할 때, Ghidra나 IDA 같은 무거운 분석 도구를 MCP(Model Context Protocol) 서버로 묶어 연결하는 방식이 일반적이다. 대표적인 사례인 REA는 이러한 도구들을 하나의 인터페이스로 통합하지만, 에이전트가 이미 셸을 통해 otool이나 nm 같은 명령줄 도구를 직접 실행할 수 있다는 점을 고려하면 MCP 계층 자체가 오히려 과부하가 될 수 있다는 지적이 나온다. leanrea 프로젝트는 이러한 맥락에서 MCP 서버 대신 8KB 크기의 SKILL.md 파일 하나로 에이전트가 대상 바이너리 종류에 맞춰 적절한 명령어를 선택하고 실행하도록 안내하는 방식을 제안한다.

작성자는 leanrea가 REA 팀의 공식 경량판이 아니며 자신과 무관하다고 명시하면서도, Claude Code(Sonnet 5.5)를 사용해 macOS 환경에서 4개 과제를 반복 테스트한 결과를 공개했다. 작성자의 주장에 따르면 leanrea 조건은 REA 조건 대비 실행 시간이 38% 짧고 비용은 35% 절감되었으며, 정답 점수는 74/75로 REA의 75/75보다 1점 낮은 수준이었다. 다만 이는 단일 모델과 머신에서의 자체 측정치이며, Claude Code가 도구 정의를 필요할 때만 불러오는 기본 설정에서는 REA MCP 서버 연결 시의 대기 컨텍스트 부담이 leanrea와 큰 차이가 없었음을 함께 언급한다.

leanrea는 별도의 분석 엔진 설치를 요구하지 않으며, 필요한 도구가 없을 경우 대체 명령을 사용하거나 사용자 동의 하에 설치하도록 유도한다. 스킬 파일은 Electron 앱, Mach-O 바이너리, Go 바이너리 등 대상 유형별로 우선 실행할 명령과 흔한 함정을 정리해 제공하며, 이후 분석 과정은 에이전트가 Bash를 통해 직접 도구를 호출해 진행한다. 다만 현재 라우터 명령 중 일부가 에이전트 실행 시 오류를 일으키는 문제가 보고되어 있으며, 2026년 10월 기준 수정을 위한 PR이 아직 병합되지 않은 상태다.
