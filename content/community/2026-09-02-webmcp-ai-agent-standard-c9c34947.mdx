에이전트가 웹을 활용하는 방식은 크게 여섯 가지로 나뉜다. 가장 직접적인 방법은 API 키를 이용해 백엔드를 호출하거나 MCP 서버를 통해 서비스를 이용하는 것이다. 이 경우 에이전트는 타입이 명확한 정확한 동작을 수행할 수 있다. 반면 현재 널리 쓰이는 방식은 사람이 보는 화면을 스크린샷이나 DOM 트리로 해석해 클릭 좌표를 계산하는 것이다. Akshay Pachaar는 이러한 접근법들이 인터페이스와의 거리와 사전 설정 필요도에 따라 차이가 있음을 지적한다.

기존 시각적 해석 방식은 데모에서는 잘 작동하지만 실제 서비스 환경에서는 취약하다. 레이아웃 변경에 민감하고 토큰 비용이 발생하며 결과의 안정성을 보장하기 어렵다. WebMCP는 이러한 문제를 해결하기 위해 웹페이지가 자신의 기능을 프로그램이 읽을 수 있는 형태로 직접 선언할 수 있게 한다. 이는 에이전트가 페이지를 못 읽는 것이 아니라, 페이지가 비인간 독자를 위한 정보를 제공하지 않았기 때문이라는 관점에서 출발한다.

WebMCP는 W3C Web Machine Learning 커뮤니티 그룹에서 논의되고 있으며 Microsoft와 Google 연구진이 초기 설명 문서를 공개했다. 현재 Chrome과 Edge에서 오리진 트라이얼이 진행 중이고 Brave와 ChatGPT 데스크톱 앱도 실험적 지원을 시작했다. 그러나 WebKit은 이 제안에 공식적으로 반대 입장을 표명했다. 따라서 WebMCP는 아직 합의된 표준이 아니라 논의가 계속 중인 제안 상태다.

이 표준은 에이전트가 웹 애플리케이션과 상호작용하는 경로를 명확히 하고자 한다. 원시 API 호출부터 시각적 해석까지 다양한 접근법 중 WebMCP는 선언형 방식을 통해 안정성을 높이고자 시도한다. 브라우저 벤더들의 입장 차이는 이 기술의 미래 방향성을 결정하는 중요한 변수가 될 것이다.
