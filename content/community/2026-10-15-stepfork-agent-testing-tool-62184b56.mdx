LLM 기반 에이전트 개발 시 가장 큰 장벽 중 하나는 실패 케이스를 일관되게 재현하는 것이다. 에이전트가 LLM 호출, 도구 사용, Python 로직 조합 등 여러 단계를 거치면 동일한 코드를 다시 실행해도 모델 응답이나 도구 출력이 달라져 버그의 원인을 파악하기 어렵다. 작성자는 이러한 외부 의존성을 고정(freeze)한 상태로 실제 애플리케이션 로직만 테스트할 수 있는 방법이 필요하다고 판단했다.

이를 위해 작성자가 개발한 Stepfork는 지원되는 LLM과 도구의 상호작용을 .sftrace 번들로 기록한다. 이 기록을 바탕으로 추가적인 모델 요청이나 도구 실행 없이 고정된 상태로 재생할 수 있으며, 도구 호출 순서와 인자의 변경을 엄격하게 감지한다. 또한 개발자가 정의한 기대값에 맞춰 pytest 회귀 테스트를 자동으로 생성해 주며, OpenAI 및 LangGraph 워크플로우와의 통합도 지원한다.

작성자는 Gemini 2.5 Flash를 사용한 합성 사고 분류 에이전트 테스트 사례를 소개했다. 모델은 중요 결제를 P0로 정확히 분류했으나, 고의적으로 삽입된 Python 후처리 버그로 인해 최종 결과가 P1로 변경되고 에스컬레이션이 비활성화되는 오류가 발생했다. Stepfork로 이 실행을 기록하고 회귀 테스트를 생성한 결과, 14개의 추적 이벤트와 5개의 도구 호출, 1회의 실제 LLM 호출이 기록되었으며 버그 있는 코드에서는 테스트가 실패하고 수정 후에는 통과하는 것을 확인했다.

이 과정은 추가적인 LLM 요청 없이 완전히 오프라인에서 재현 가능하며, Gemini API 키 없이도 전체 실험을 반복할 수 있다고 작성자는 밝혔다. 다만 Stepfork는 아직 초기 알파 버전이라 고정 재생이 계측된 의존성만 대체하고 임의의 사이드 이펙트까지 처리하지는 못한다. 샌드박스 환경은 아니며 개발자가 기대 결과를 직접 정의해야 한다는 한계가 있다. 작성자는 Hugging Face 모델과 에이전트 프레임워크를 사용하는 개발자들의 재현 가능한 테스트 접근 방식에 대한 피드백을 요청했다.
