# 초록 (Chorok) design system

**새 화면을 설계하러 왔다면 `brief.md` 를 먼저 읽어라.** 계보·재료·긴장 축·파격 예산·아직 안 정한 것들이 거기 있다.
이 문서는 그 다음에 필요한 것 — **손잡이가 어디 있고 무엇이 이미 만들어져 있는가**이다.

「초록」은 HuggingFace 블로그와 arXiv 논문을 읽고 한글로 추려 적는 1인 지면이다. 이름은 논문 맨 앞의 초록(抄錄) —
전문 번역이 아니라 **골라서 옮겨 적은 것**이라는 성격이 이름에 들어 있다. 계보는 **신문 지면**이다.

## 이 시스템의 성격

규칙집이 아니라 **손잡이(knob) 모음**이다. 잠긴 것은 넷뿐이고, 나머지 값은 전부 돌려 쓰라고 만들어 뒀다.

**불변 넷** — 이것만 지키면 무엇을 해도 「초록」이다.

1. **두 목소리** — 한글 명조와 원문 mono 를 섞지 않는다.
2. **안료 팔레트** — 낮은 채도, 공통 명도 척도. 형광·그라디언트·발광 없음.
3. **손으로 정한 척도** — 간격이 8의 배수가 아니다.
4. **떠 있지 않은 지면** — 그림자로 높이를 만들지 않는다.

**나머지는 전부 손잡이다.** 기본값은 의견이 세지만 어느 것도 잠겨 있지 않다.
`radius` 가 0 인 것도, 목록이 밀집인 것도, 레일이 왼쪽인 것도 취향이지 규칙이 아니다 —
토큰 하나 고치면 전체가 따라온다.

## 쓰는 법

- 모든 페이지에서 스타일시트 하나만 링크한다 — `<link rel="stylesheet" href="styles.css">` (상대 경로는 맞춰서).
  색·글꼴·간격·반경·그림자는 전부 그 안의 변수(`var(--color-*)`, `var(--font-*)`, `var(--space-*)`,
  `var(--radius-*)`, `var(--shadow-*)`)에서 가져온다. 토큰이 이미 갖고 있는 hex·글꼴 이름·px 값을 직접 쓰지 마라.
  **이게 이 시스템의 유일한 진짜 규칙이다** — 값을 복제하는 순간 디자인 변경이 코드를 통과하지 못한다.
- 컴포넌트 페이지는 순수 HTML 이다. 소스를 열어 마크업을 가져다 쓰고, 필요하면 고쳐 쓴다.
- 여기 없는 컴포넌트가 필요하면 **만들어라.** 토큰만 쓰면 시스템 안에 있는 것이다.

## 손잡이

| 토큰 | 지금 값 | 돌리면 |
|---|---|---|
| `--radius-sm/md/lg` | 2px | 각진 지면 ↔ 부드러운 지면 |
| `--space-1…9` | 5·9·14·18·28·37·55·74·110 | 전체 밀도 (8의 배수만 피하면 된다) |
| `--measure` | 68ch | 본문 한 줄 길이 |
| `--rail` | 136px | 좌측 메타 열 폭 (arXiv 식별자 한 줄 기준) |
| `--page-max` | 1080px | 지면 폭 |
| `--entry-pad` | `--space-3` | 목록 밀도 — 화면마다 덮어써도 된다 |
| `--rule-hair` | 1px | 괘선 굵기 |
| `--text-h1…h6`, `--text-body` | 40 / 27 / 21 / 17 / 15 / 13, 16.5 | 활자 급. 신문 지면은 급 차이가 클수록 산다 |
| `--leading-body` | 1.85 | 한글 본문 행간 |

## 색

바탕은 낮 `oklch(0.968 0.006 85)`, 밤 `oklch(0.175 0.008 80)`. 둘 다 채도가 살짝 있는 따뜻한 중성 —
순백도 순검정도 쓰지 않는다. 두 모드는 서로의 반전이 아니라 같은 종이의 두 시간이다.

안료 셋은 각각 100–900 단계를 가지며 OKLCH **공통 명도 척도** 위에 있다. 같은 단계의 세 안료는 시각적 무게가 같다.
낮 바탕에서는 600, 밤 바탕에서는 300 이 그 역할의 기본값으로 자동 배정된다.

| 역할 | 안료 | 쓰는 곳 |
|---|---|---|
| `--color-accent` | 草綠 | 최신 논문 · 포커스 링 |
| `--color-accent-2` | 朱土 | 허깅페이스 소식 |
| `--color-accent-3` | 藍 | 수집 자료 |

草綠 ramp 만 채도가 한 단계 높다. 녹색은 같은 채도에서 지각적으로 가장 무채색에 가깝게 읽히기 때문이다 —
실측하고 올린 값이다.

**링크는 색으로 표시하지 않는다.** 밑줄이 링크를 가리키고 색 예산은 카테고리에 쓴다.
안료를 셋이나 쓰면서도 산만해지지 않는 이유다. (이건 강한 기본값이지 불변은 아니다 —
링크를 색으로 바꾸고 싶으면 카테고리 부호를 다른 재료로 옮기면 된다.)

한자(抄錄·草綠·朱土·藍)는 **색 이름과 부제에만** 쓴다. 화면 본문에는 내보내지 않는다.

## 활자

제목과 본문 모두 **Noto Serif KR**(`--font-heading` / `--font-body`). 한글 명조는 같은 px 에서 산세리프보다 작아
보이므로 본문을 16.5px, 행간을 1.85 로 둔다. `word-break: keep-all` 은 base 에 박혀 있다.

- `--font-mono` (IBM Plex Mono) — 날짜·식별자·수치·도메인. **이 자리에 한글이 오면 안 된다** (한글 글리프가 없어
  폴백으로 샌다). 제약을 규칙으로 바꾼 것이다.
- `--font-ui` (IBM Plex Sans KR) — 작은 한글 라벨·태그·버튼.

한글에는 이탤릭이 없다. 강조는 기울임이 아니라 **급과 굵기**로 만든다.

## 상호작용 상태

브라우저 기본값을 그대로 두지 않는다. 링크 호버는 밑줄이 `--color-line` 에서 currentColor 로 진해지고,
키보드 포커스는 `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 3px; }` —
사이트 이름의 색(草綠)이 "지금 여기"를 가리킨다. `::selection` 은 안료 틴트다.

## 이미 만들어져 있는 것

| 클래스 | 무엇인가 |
|---|---|
| `.voice-source` | 원문의 목소리 — mono 메타 (날짜·식별자·수치). 중간에서 끊기지 않는다 |
| `.voice-ui` | 작은 한글 라벨 — 산세리프 |
| `.kicker` | 절 머리글 — 자간 넓힌 소형 대문자 |
| `.entry` + `.entry-rail` · `.entry-title` · `.entry-meta` | 목록 한 항목 — 좌측 메타 레일 + 본문 |
| `.cat-papers` · `.cat-news` · `.cat-notes` | 카테고리 스코프 — `--cat` 을 정한다 |
| `.cat-label` | 카테고리 이름, `--cat` 색으로 |
| `.tag` | 태그 칩 |
| `.ground-light` · `.ground-dark` | 한 페이지에서 낮/밤을 나란히 보여줄 때 |
| `.rule` | 얇은 가로선 |
| `.page` | 지면 컨테이너 |
| `.rule-pair` | 굵은선/얇은선 쌍 — 1면 머리 장식. 한 화면에 한 번 |
| `.masthead` + `-title` · `-line` · `-meta` | 제호. 히어로가 아니다 |
| `.dateline` | 날짜·출처·식별자 한 덩이 |
| `.headline` · `.deck` · `.lede` | 표제 / 부제 / 리드 — 세 단계로 들어간다 |
| `.entry-lead` | 머리기사 — 지면당 하나, 급을 스케일 밖으로 키워도 된다 |
| `.brief-set` · `.brief-item` | 단신 — 짧은 것은 뭉쳐서 |
| `.index-row` + `.index-no` | 색인 — 되찾기용, 가장 밀집. 맨 앞이 축 번호 |
| `.count-bar` | 분포 막대 — 편수의 기울기를 길이로. **먹만 쓴다** |
| `.list-tight` · `.list-loose` | 목록 밀도 스코프 |
| `.btn` · `.btn-quiet` · `.input` | 컨트롤. 채우기 없음, 상자 대신 밑줄 |
| `.empty` + `-line` · `-next` | 빈 상태 — 사과하지 않고 다음 갈 곳을 준다 |
| `.ratio` | **시그니처** — 추린 비율. 데이트라인 안의 한 조각 |
| `.ratio-scale` + `-row` · `-key` · `-track` · `-fill` | **시그니처** — 추린 비율 확장형. 기사면에서 한 번만 |

목록은 짧다. **의도한 것이다** — 정해 둔 컴포넌트가 많을수록 새 화면은 조립이 되고, 조립된 화면은 편집된 것처럼
보이지 않는다. 필요한 것을 그때그때 만들어 쓰고, 두 번 이상 쓰인 것만 여기로 올린다.

## 앱과의 관계

**디자인이 정본이고 코드가 따라온다.** 앱(Next.js · Tailwind v4)은 이 파일의 `:root` 토큰 블록을 받아쓰며,
값을 따로 갖지 않는다. 그래야 이후 디자인 변경이 코드를 거치지 않고 흐른다.
앱에서 `#1c1a16` 같은 값이나 `Noto Serif KR` 같은 글꼴 이름이 직접 발견되면, 그건 고쳐야 할 결함이다.

### 시그니처가 앱에 요구하는 것

디자인이 콘텐츠 규약을 요구하는 두 자리다. 이것만 앱이 채워 주면 나머지는 이 시스템이 그린다.

| 시그니처 | 필요한 것 | 비고 |
|---|---|---|
| 추린 비율 | frontmatter 에 **원문 길이** 한 필드 | 초록 쪽 길이는 본문에서 세면 된다 — 적을 필요 없다 |
| 1면 편집 | frontmatter 에 **`lead`** (선택) | 없으면 **그날 여러 곳에서 같이 나온 글** 중 최신, 그것도 없으면 최신 글. 머리기사는 **가장 새 날에만** 선다 (한 호 = 하루) |

필드 이름은 앱의 스키마 규칙을 따르되, **한번 정하면 바꾸지 않는다** — 이미 발행한 글을 전부 고쳐야 하기 때문이다.

## 파일

- `brief.md` — **설계할 때 읽는 문서.** 계보·독자·재료·긴장 축·시그니처·파격 예산·빈칸·실패 신호.
- `styles.css` — 유일한 스타일시트. 토큰 블록 + 컴포넌트 층.
- `theme.json` — 파라미터의 기계 판독용 기록.
- `readme.md` — 이 문서.
- `thumbnail.html` — 프로젝트 표지.
- `foundations/color.html` — 낮/밤 바탕, 안료 ramp 4종, 카테고리 역할.
- `foundations/type.html` — 두 목소리, 활자 급, 실제 목록 항목에 얹은 모습.
- `foundations/layout.html` — 레일과 지면, 본문 폭, 간격 척도, 가장자리 처리.
- `components/signatures.html` — **시그니처 후보 다섯. 아직 고르지 않았다** — 고른 것만 `styles.css` 로 승격한다.
- `components/entries.html` — 목록 항목 성격 셋(머리기사·단신·색인), 밀도 셋, 커버 있는 글 문제.
- `components/masthead.html` — 제호·내비·괘선 쌍·푸터.
- `components/article.html` — 기사면. 데이트라인, 표제/부제/리드, 원문 출처, 본문 재료.
- `components/controls.html` — 버튼·태그·검색 필드·빈 상태, 그리고 "지난번 이후 새것"의 빈칸.
