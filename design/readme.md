# 초록 (Chorok) design system

**새 화면을 설계하러 왔다면 `brief.md` 를 먼저 읽어라.** 계보·재료·긴장 축·파격 예산·아직 안 정한 것들이 거기 있다.
이 문서는 그 다음에 필요한 것 — **손잡이가 어디 있고 무엇이 이미 만들어져 있는가**이다.

「초록」은 HuggingFace 블로그와 arXiv 논문을 읽고 한글로 추려 적는 1인 지면이다. 이름은 논문 맨 앞의 초록(抄錄) —
전문 번역이 아니라 **골라서 옮겨 적은 것**이라는 성격이 이름에 들어 있다. 계보는 **개발자 도구**다
(Linear · Vercel · Raycast). 옛 계보였던 신문 지면이 왜 죽었는지는 `brief.md` 의 사망 기록에 있다.

## 이 시스템의 성격

규칙집이 아니라 **손잡이(knob) 모음**이다. 잠긴 것은 넷뿐이고, 나머지 값은 전부 돌려 쓰라고 만들어 뒀다.

**불변 넷** — 이것만 지키면 무엇을 해도 「초록」이다.

1. **한 목소리 + mono** — 한글 산문은 산세리프 한 벌(IBM Plex Sans KR), mono 는 손대지 않은 원문 재료에만.
2. **액센트 1색** — 草綠 `oklch(0.715 0.190 148)`. 지면에서 채도가 높은 색은 이 하나뿐이다.
3. **다크가 기본 지면** — 라이트는 사용자의 명시적 선택이지 OS 의 선택이 아니다.
4. **부호는 열에 앉는다** — 제목 왼쪽에 오는 것은 전부 폭이 고정된 열(썸네일 80px · 축 번호 26px).

옛 불변 넷(두 목소리 · 안료 팔레트 · 손으로 정한 척도 · 떠 있지 않은 지면)이 어떻게 됐는지는
`brief.md` 「사망: 옛 불변 넷 (2026-08-20)」에 있다. **「떠 있지 않은 지면」은 죽은 게 아니라
계보로 옮겨 갔다** — 입체는 여전히 그림자가 아니라 위 모서리 1px(`--edge-top`)이 만든다.

**나머지는 전부 손잡이다.** 기본값은 의견이 세지만 어느 것도 잠겨 있지 않다 —
토큰 하나 고치면 전체가 따라온다.

## 쓰는 법

- 모든 페이지에서 스타일시트 하나만 링크한다 — `<link rel="stylesheet" href="styles.css">` (상대 경로는 맞춰서).
  색·글꼴·간격·반경·그림자는 전부 그 안의 변수에서 가져온다. 토큰이 이미 갖고 있는 hex·글꼴 이름·px 값을
  직접 쓰지 마라. **이게 이 시스템의 유일한 진짜 규칙이다** — 값을 복제하는 순간 디자인 변경이 코드를 통과하지 못한다.
- 컴포넌트 페이지는 순수 HTML 이다. 소스를 열어 마크업을 가져다 쓰고, 필요하면 고쳐 쓴다.
- 여기 없는 컴포넌트가 필요하면 **만들어라.** 토큰만 쓰면 시스템 안에 있는 것이다.

### 이름 규칙 — 원료와 역할을 섞지 마라

토큰은 두 층이고 **이름 공간이 다르다.** 2026-08-20 개편에서 세운 규칙이다.

| 층 | 이름 | 누가 소유하나 | 예 |
|---|---|---|---|
| **원료** | `--color-*` · `--text-*` · `--radius-*` | Tailwind 이름 공간 — 앱에서 `@theme` 가 받는다 | `--color-ink-950` · `--color-green-500` · `--text-body` · `--radius-md` |
| **역할** | 접두사 없는 이름 | 우리 층 — `:root`(정본은 `:root`/`.ground-*`)가 소유한다 | `--bg` · `--muted` · `--accent` · `--cat-paper` · `--space-4` |

원료는 지면이 바뀌어도 안 변하고, 역할은 낮/밤마다 갈린다.
그래서 앱에서 `@theme inline { --color-bg: var(--bg) }` 가 **자기참조가 아니게 된다** —
개편 전에는 원료와 역할이 같은 이름 공간에 있어 불가능했고, 그 때문에 안료 ramp 를 유틸리티로 못 올리고 있었다.

## 손잡이

| 토큰 | 지금 값 | 돌리면 |
|---|---|---|

## 색

**밤이 기본 지면이다.** 바탕은 밤 `--color-ink-950`(`#0b0f14`), 낮 `#ffffff`.
두 지면은 서로의 반전이 아니라 각각 따로 정해진 값이고, 낮은 사람이 고를 때만 온다.

원료는 두 ramp 뿐이다.

- **먹** `--color-ink-50` … `--color-ink-975` — **색상 255 고정.** 옛 척도는 85 → 70 으로 흘러서
  밝은 쪽이 미색(신문 용지)으로 읽혔다. 채도는 작지만 0 이 아니다 — 순회색은 「설정하지 않은 관리자 화면」이다.
- **草綠** `--color-green-100` … `--color-green-800` — **색상 148.** 140 이 아닌 이유: 140 은 채도를
  올릴수록 형광 연두로 간다.

### 역할

| 역할 토큰 | 밤 (기본) | 낮 |
|---|---|---|
| `--bg` | `--color-ink-950` | `#ffffff` |
| `--surface` | `--color-ink-900` | `--color-ink-50` |
| `--border` | `--color-ink-800` | `--color-ink-200` |
| `--body` · `--heading` | `--color-ink-100` | `--color-ink-900` |
| `--muted` | `--color-ink-400` | `--color-ink-600` |
| `--faint` | `--color-ink-600` | `--color-ink-400` |
| `--accent` | `--color-green-500` | `--color-green-700` |

`--faint` 는 **바탕 대비가 본문 기준(4.5:1)에 못 미친다.** 구분 기호·비활성처럼 정보를 담지 않는 곳에만 써라.

### 카테고리 부호 — 다섯 칸

`src/lib/categories.ts` 의 `accent` 키와 짝이다. **안료 3색 + 먹 2단계**이고,
**채도가 액센트의 절반도 안 된다**(C 0.05 대 0.19) — 부호가 액센트를 이기면 한 화면에 고채도 색이
여섯이 되고 불변 2가 무너진다.

| 역할 토큰 | 카테고리 | 안료 | 스코프 클래스 |
|---|---|---|---|
| `--cat-paper` | `papers` 논문 | 草綠 (저채도) | `.cat-papers` |
| `--cat-release` | `releases` 릴리즈 | 朱土 | `.cat-releases` |
| `--cat-news` | `news` 소식 | 藍 | `.cat-news` |
| `--cat-community` | `community` 커뮤니티 | **먹 中** | `.cat-community` |
| `--cat-note` | `notes` 기록 | **먹 濃** | `.cat-notes` |

**색을 안 쓰는 것 자체가 부호다** — `community` 는 원문이 여럿이라 하나를 가리킬 수 없고,
`notes` 는 원문이 아니라 **사람이 골랐다는 것**이 기준이다. 먹 2칸은 안료와 달리 자동으로 뒤집히지
않는다: 낮의 명도 순서(中 < 濃)를 밤에서도 지키려면 밝은 쪽으로 옮겨야 한다.

다섯 칸 전부 **두 지면 모두에서 AA 4.5:1 을 넘는다.** 그래서 지면별로 손선택하던
`dark:` 변형과 700/300 짝짓기가 통째로 사라졌다.

> **2026-08-20 철회 — 「링크는 색으로 표시하지 않는다. 늘 밑줄이 그어져 있다」.**
> 그것은 신문 지면의 관습이고, 균일 피드에서는 스무 행이 전부 밑줄이라 행과 행의 구분이 오히려
> 사라진다. **밑줄은 이제 hover·focus 에서만 온다.** 링크에 색 예산을 쓰지 않는다는 원칙 자체는 그대로다 —
> 지면에서 액센트가 오는 자리는 「추린 비율」과 포커스 링이다.

한자(抄錄·草綠·朱土·藍)는 **색 이름과 부제에만** 쓴다. 화면 본문에는 내보내지 않는다.

## 활자

**한 벌이다.** 제목·본문·작은 라벨 전부 **IBM Plex Sans KR**
(`--font-heading` / `--font-body` / `--font-ui` 가 같은 스택을 가리킨다).
명조(Noto Serif KR)를 뺀 것이 2026-08-20 개편이다 — 한글 패밀리가 둘에서 하나로 줄어 FOUT 이 절반이고,
Plex Sans KR 과 Plex Mono 는 **같은 슈퍼패밀리**라 「한 목소리 + mono」의 관계가 자의적이지 않다.

- `--font-mono` (IBM Plex Mono) — 날짜·식별자·수치·도메인. **이 자리에 한글이 오면 안 된다**
  (한글 글리프가 없어 폴백으로 샌다). 제약을 규칙으로 바꾼 것이다.
- 본문 15.5px · 행간 1.7. 제목은 1.25 로 조이고 자간 -0.012em.
- `word-break: keep-all` 은 base 에 박혀 있다. 한글에는 이탤릭이 없다 — 강조는 **급과 굵기**로.
- 굵기는 400 / 500 / 600 셋뿐이다. 700 을 쓰지 마라.

## 상호작용 상태

브라우저 기본값을 그대로 두지 않는다. 링크는 hover·focus 에서 밑줄이 올라오고,
키보드 포커스는 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 3px; }` —
사이트 이름의 색(草綠)이 "지금 여기"를 가리킨다. `::selection` 은 안료 틴트다.

**2026-08-20 에 목록에서 빠진 것:** `.entry-lead`(머리기사) · `.brief-set` · `.brief-item`(단신 묶음).
「1면 편집」시그니처가 죽으면서 앱 쪽 컴포넌트(`PostLead` · `PostBrief`)가 통째로 사라졌다
(`brief.md` 사망 기록). **CSS 규칙도 같은 날 `styles.css` 에서 지웠다** — 죽은 클래스를 남기면
다음 사람이 그것을 쓴다. 그 자리에는 사망 사실만 날짜와 함께 주석으로 남아 있다.

목록은 짧다. **의도한 것이다** — 정해 둔 컴포넌트가 많을수록 새 화면은 조립이 되고, 조립된 화면은 편집된 것처럼
보이지 않는다. 필요한 것을 그때그때 만들어 쓰고, 두 번 이상 쓰인 것만 여기로 올린다.

## 앱과의 관계

**디자인이 정본이고 코드가 따라온다.** 앱(Next.js · Tailwind v4)은 이 파일의 `:root` 토큰 블록을 받아쓰며,
값을 따로 갖지 않는다. 그래야 이후 디자인 변경이 코드를 거치지 않고 흐른다.

### 이건 이제 부탁이 아니라 게이트다

`src/lib/design-tokens.test.ts` 가 **정본(`design/styles.css`)과 앱(`src/app/globals.css`)을 파싱해
직접 비교한다.** 값을 복제하거나 한쪽만 고치면 `npm run test` 가 깨진다.

잡는 결함:

- 정본 `:root` 의 **모든** 토큰이 앱에 같은 값으로 있는가 (첫 실행에서 `1.70` 대 `1.7` 을 잡았다)
- 정본 `.ground-light` 와 앱 `.light` 가 같은가 — 밤은 `:root` ↔ `:root` 라 위 항목이 이미 본다
- `@theme inline` 의 이름이 전부 실제로 유틸리티로 쓰이는가 (안 쓰이면 Tailwind 가 빌드에서 지운다)
- 컴포넌트에 hex · `oklch()` · 글꼴 이름 리터럴이 **0** 인가
- 컴포넌트와 CSS 가 참조하는 `var(--…)` 가 전부 정의돼 있는가 (**죽은 참조는 조용히 무색이 된다**)
- `CAT_CLASS` 다섯 클래스가 CSS 에 전부 있는가 (CSS 누락은 컴파일러가 못 잡는다)
- 앱이 정의한 클래스가 정본에도 있는가 — **`.row` 가족이 정본에 없는 채로 발행된 것이 이 항목의 계기다**
- 모든 안료가 sRGB 색역 안인가 · 본문과 부호가 두 지면 모두에서 AA 4.5:1 을 넘는가
- 부호의 채도가 액센트의 절반 미만인가
- 소셜 카드 hex 가 정본 안료와 같은 색인가 (satori 는 `oklch()` 를 못 읽어 굽는다)

앱에서 `#1c1a16` 같은 값이나 `Noto Serif KR` 같은 글꼴 이름이 직접 발견되면, 그건 고쳐야 할 결함이고
이제 테스트가 그 자리에서 잡는다.

### 시그니처가 앱에 요구하는 것

디자인이 콘텐츠 규약을 요구하는 자리다. 이것만 앱이 채워 주면 나머지는 이 시스템이 그린다.

| 시그니처 | 필요한 것 | 비고 |
|---|---|---|
| 추린 비율 | frontmatter `source.words` (원문 길이) | 초록 쪽 길이는 본문에서 세면 된다 — 적을 필요 없다. **없으면 그 글에는 그리지 않는다** |
| 선별 경위 | frontmatter `selection` (`crossSources` · `popularity` · 축 신뢰도) | **사람이 고른 글(`notes`)에는 없다** — 고른 주체가 사람이다 |
| 썸네일 | frontmatter `source.image` (원문 페이지의 그림 주소) | 선택. 없으면 표지가 선다. **복제가 아니라 임베드다** (ADR-014) |

필드 이름은 앱의 스키마 규칙을 따르되, **한번 정하면 바꾸지 않는다** — 이미 발행한 글을 전부 고쳐야 하기 때문이다.

> **2026-08-20 — 「모든 행에」를 「행마다, 있는 만큼」으로 고쳤다.** 옛 규칙(「한 지면에 한 번」)에서
> 바뀐 것은 **아끼지 않기로 한 것**이지 「전부 채운다」가 아니다. 80편 중 39편은 원문 단어 수를 못 재서
> (한글 소스·유튜브·티저 RSS) 비어 있고, **추측해서 채우지 않는다** — 비는 것은 결함이 아니라 사실이다.
> 화면은 **빈 자리를 예약하지 않는 것**으로 이것을 받는다: 비율이 왼쪽 무리의 마지막 칸이라
> 없어도 뒤에서 밀릴 것이 없다 (`design/stitch/NOTES.md` ⑤). `—` 를 찍지 않는 이유다.

## 파일

- `brief.md` — **설계할 때 읽는 문서.** 계보·독자·재료·긴장 축·시그니처·파격 예산·빈칸·실패 신호·**사망 기록**.
- `styles.css` — 유일한 스타일시트. 토큰 블록 + 컴포넌트 층.
- `theme.json` — 파라미터의 기계 판독용 기록.
- `readme.md` — 이 문서.
- `thumbnail.html` — 프로젝트 표지.
- `stitch/DESIGN.md` · `stitch/NOTES.md` — **눈으로 정해야 했던 숫자 넷**(액센트·radius·행 높이·썸네일)을
  stitch 로 정한 기록과, 취한 것 / 버린 것 / 왜. 생성된 코드는 한 줄도 이식하지 않았다.
- `foundations/color.html` · `type.html` · `layout.html` · `components/*.html` — 실제 크기 프리뷰.

> **프리뷰 HTML 9개는 2026-08-20 에 전부 갱신했다.** 색·활자·간격은 `styles.css` 를 링크하므로 늘 따라왔고,
> 이번에 **설명 문구까지** 지금 것으로 맞췄다 — 균일 피드 `.row` 와 색인 `.index-row`(머리기사·단신은 죽었다) ·
> 한글 산세리프 한 벌 + mono(명조는 죽었다) · 원료 ramp 둘(먹 12칸 + 草綠 6칸)에 카테고리 역할 5칸 ·
> 4px 간격 척도 · 모서리 4px · 66ch / 104px / 960px · 밤이 기본 지면 · 카테고리 다섯 칸의 이름.
> 그래도 **값은 `styles.css` 에서 읽어라** — 프리뷰는 설명이지 정본이 아니다.
